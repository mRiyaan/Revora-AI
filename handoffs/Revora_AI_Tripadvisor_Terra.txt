5. EXACT API CONTRACT (MIMICS TRIPADVISOR TERRA API + REPUTATION MGMT KIT)
--------------------------------------------------------------------------------
All API routes MUST include CORS headers allowing `http://localhost:3000` and
`http://localhost:4000` (plus `OPTIONS` preflight returning `204`):
  Access-Control-Allow-Origin: *
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
  Access-Control-Allow-Headers: Content-Type, Authorization, x-oauth-token, accept

Persistence:
  Store reviews in a local JSON file: `apps/mock-tripadvisor/data/reviews.json`
  Seed at least 15 realistic fictional reviews across all 3 allowlisted
  locations (`187147`, `188151`, `190420`) covering all 6 hackathon scenarios:
  praise, suggestions, cleanliness, billing, safety, and mixed.

Authentication Rule on Terra Endpoints:
  Check `x-oauth-token` header === `sandbox-terra-jwt`
  (or `process.env.SANDBOX_TERRA_OAUTH_TOKEN || "sandbox-terra-jwt"`).
  If missing or invalid on `/api/allowlist` or `/api/locations/**`, return `401`
  with `Content-Type: application/problem+json`:
    {
      "type": "https://terra.tripadvisor.com/errors/unauthorized",
      "title": "Unauthorized",
      "status": 401,
      "detail": "Missing or invalid x-oauth-token header."
    }

Allowlist Enforcement Rule:
  Allowed IDs come from `process.env.TERRA_ALLOWLIST_IDS || "187147,188151,190420"`.
  If `:id` is NOT in the allowlist, return `404 Not Found`
  (`Content-Type: application/problem+json`):
    {
      "type": "https://terra.tripadvisor.com/errors/location-not-allowlisted",
      "title": "Location Not Found or Not Allowlisted",
      "status": 404,
      "detail": "Location ID is not in your Terra API allowlist."
    }

NOTE: Tripadvisor Terra does NOT push webhooks. Revora AI CRM polls these
endpoints directly.

--- Endpoint 1: Get Allowlist (Mimics `GET /api/allowlist`) ---
GET /api/allowlist
  Response `200 OK`:
    {
      "data": [187147, 188151, 190420],
      "pagination": { "size": 1000, "next_cursor": null }
    }

--- Endpoint 2: List Location Reviews (Mimics `GET /api/locations/{id}/reviews`) ---
GET /api/locations/:id/reviews
  Query params: `cursor` (optional)
  Dynamic Moderation Status on Every GET:
    - If `owner_response` has `publish_after_ms`, compute dynamically:
      `status = Date.now() < owner_response.publish_after_ms ? "PENDING_MODERATION" : "PUBLISHED"`
  Response `200 OK`:
  {
    "data": [
      {
        "id": 301001,
        "location_id": 187147,
        "title": "Lovely stay, minor housekeeping delay",
        "text": "The pool and dining were wonderful, though extra towels took an hour to arrive.",
        "rating": 4,
        "published_date": "2026-11-24T11:00:00Z",
        "trip_type": "Family",
        "user": { "username": "PriyaM_Travels" },
        "subratings": {
          "cleanliness": 3,
          "service": 5,
          "value": 4,
          "rooms": 4
        },
        "owner_response": null
      }
    ],
    "pagination": { "next_cursor": null }
  }

--- Endpoint 3: Get Single Review ---
GET /api/locations/:id/reviews/:reviewId
  Response `200 OK`: `{ "data": { ...TerraReview } }` (or `404`).

--- Endpoint 4: Submit Owner Response (Mimics `POST .../owner-responses`) ---
POST /api/locations/:id/reviews/:reviewId/owner-responses
  Required Headers:
    `x-oauth-token: sandbox-terra-jwt`
    `Content-Type: application/json`
  Request Body:
    {
      "author_connection": "General Manager",
      "language": "en",
      "text": "Thank you for your feedback! We have shared this with our housekeeping lead."
    }
  Strict Terra Validation Rules (MUST IMPLEMENT):
    1) Check location is in allowlist and review belongs to `:id` (else `404`).
    2) Duplicate Protection (`409 Conflict`, `application/problem+json`):
       If `review.owner_response` already exists, return `409`:
       {
         "type": "https://terra.tripadvisor.com/errors/conflict",
         "title": "Owner Response Already Exists",
         "status": 409,
         "detail": "An owner response has already been submitted for this review. Delete it before submitting another."
       }
    3) Field & Moderation Validation (`400 Bad Request`, `application/problem+json`):
       - `author_connection` required, 1–128 chars
       - `language` required (e.g. `"en"`)
       - `text` required, non-empty
       - Reject URLs (`http://`, `https://`, `www.`), emails, or 10+ digit phone numbers
       Return `400` problem+json explaining the policy/field violation.
  Valid Behavior:
    - Save on the review in `data/reviews.json`:
      `owner_response: { id: "resp_" + Date.now(), author_connection, language, text, published_date: new Date().toISOString(), publish_after_ms: Date.now() + 2000, status: "PENDING_MODERATION" }`
  Response `201 Created`:
    {
      "id": "resp_1732520000",
      "author_connection": "General Manager",
      "language": "en",
      "text": "...",
      "published_date": "2026-11-25T13:45:00.000Z",
      "status": "PENDING_MODERATION"
    }

--- Endpoint 5: Get Owner Response ---
GET /api/locations/:id/reviews/:reviewId/owner-responses
  Response `200 OK`: `owner_response` object (or `404` if none exists).

--- Endpoint 6: Delete Owner Response ---
DELETE /api/locations/:id/reviews/:reviewId/owner-responses
  Behavior: Sets `owner_response: null` in `data/reviews.json`.
  Response `204 No Content`.

--- Endpoint 7: UI Traveler Review Submission ---
POST /api/ui/reviews
  (Called by the mock website's "Write a Review" modal.)
  Request Body:
    {
      "location_id": 187147,
      "title": "Outstanding hospitality",
      "text": "...",
      "rating": 5,
      "trip_type": "Couples",
      "username": "Traveler_Riya"
    }
  Response `201 Created`:
    { "data": { ...TerraReview } }
