5. EXACT API CONTRACT (MIMICS BOOKING.COM CONNECTIVITY GUEST REVIEW API)
--------------------------------------------------------------------------------
All API routes MUST include CORS headers allowing `http://localhost:3000` and
`http://localhost:4000` (plus `OPTIONS` preflight returning `204`):
  Access-Control-Allow-Origin: *
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
  Access-Control-Allow-Headers: Content-Type, Authorization

Persistence:
  Store reviews in a local JSON file: `apps/mock-booking/data/reviews.json`
  Seed at least 15 realistic fictional reviews across all 3 properties
  (`800101`, `800102`, `800103`) covering all 6 hackathon scenarios: praise,
  suggestions, cleanliness, billing, safety, and mixed.

Authentication Rule on `/api/review-api/**`:
  Check `Authorization` header === `Bearer sandbox-booking-jwt`
  (or `process.env.SANDBOX_BOOKING_TOKEN || "sandbox-booking-jwt"`).
  If missing or invalid, return HTTP `401` JSON:
    {
      "errors": [{ "code": "UNAUTHORIZED", "message": "Invalid or missing machine account JWT" }],
      "warnings": [],
      "meta": { "ruid": "sandbox-ruid-401" }
    }

NOTE: Booking.com Connectivity does NOT provide push webhooks. Revora AI CRM
polls these endpoints directly.

--- Endpoint 1: Retrieve Reviews ---
GET /api/review-api/properties/:property_id/reviews
  Query params:
    - from_date (optional, YYYY-MM-DD)
    - limit (optional, default 50)
    - cursor (optional)
  Validation:
    - Return 404 if property_id not in ["800101", "800102", "800103"].
  Dynamic Moderation Status Computation on Every GET:
    - If a review has a `reply` with `publish_after_ms`, compute dynamically:
      `status = Date.now() < reply.publish_after_ms ? "PENDING_MODERATION" : "PUBLISHED"`
  Response `200 OK`:
  {
    "errors": [],
    "warnings": [],
    "meta": {
      "ruid": "sandbox-ruid-001",
      "next_page": null
    },
    "data": {
      "reviews": [
        {
          "review_id": "bk_rev_201",
          "property_id": "800101",
          "reservation_id": "RES-994821",
          "reviewer_name": "Karan Mehta",
          "created_timestamp": "2026-11-24 14:10:00",
          "last_change_timestamp": "2026-11-24 14:10:00",
          "review_score": 4.0,
          "content": {
            "language_code": "en",
            "headline": "Overcharged at checkout",
            "positive": "Great breakfast and central location.",
            "negative": "Booked for ₹5,000 but billed ₹6,200 at checkout with unexplained charges."
          },
          "scores": {
            "cleanliness": 8.0,
            "comfort": 7.0,
            "location": 9.0,
            "facilities": 7.0,
            "staff": 5.0,
            "value_for_money": 2.0
          },
          "traveler_type": "Business",
          "reply": null
        }
      ]
    }
  }
  NOTE: `review_score` is on Booking.com's 10-point scale (`1.0` to `10.0`)!

--- Endpoint 2: Retrieve Single Review ---
GET /api/review-api/properties/:property_id/reviews/:review_id
  Response `200 OK`:
    { "errors": [], "warnings": [], "meta": { "ruid": "..." }, "data": { "review": { ... } } }

--- Endpoint 3: Post Property Reply (With Booking.com Moderation Pipeline) ---
POST /api/review-api/properties/:property_id/reviews/:review_id/replies
  Request Body:
    {
      "text": "Thank you for sharing your feedback...",
      "language_code": "en"
    }
  Validation & Moderation Rules (MUST IMPLEMENT):
    1) Check `text` is 1–2000 characters.
    2) Reject external URLs (`http://`, `https://`, `www.`), email addresses,
       or 10+ digit phone numbers (Booking.com content policy blocks off-platform
       contact info / links) with `400 Bad Request`:
       {
         "errors": [{
           "code": "MODERATION_REJECTED",
           "message": "External URLs, email addresses, or phone numbers are not permitted in Booking.com replies."
         }],
         "warnings": [],
         "meta": { "ruid": "sandbox-ruid-400" }
       }
  Valid Behavior:
    - Store on the review in `data/reviews.json`:
      `reply: { reply_id: "rep_" + Date.now(), created_timestamp, text, language_code: language_code || "en", publish_after_ms: Date.now() + 2000, status: "PENDING_MODERATION" }`
  Response `201 Created`:
    {
      "errors": [],
      "warnings": [],
      "meta": { "ruid": "sandbox-ruid-201" },
      "data": {
        "success": true,
        "reply_id": "rep_1732520000",
        "status": "PENDING_MODERATION",
        "last_change_timestamp": "2026-11-25 13:45:00"
      }
    }

--- Endpoint 4: Check Reply Moderation Status ---
GET /api/review-api/properties/:property_id/reviews/:review_id/replies/:reply_id
  Response `200 OK`:
    {
      "errors": [],
      "warnings": [],
      "meta": { "ruid": "sandbox-ruid-status" },
      "data": {
        "reply_id": "...",
        "status": "PENDING_MODERATION" | "PUBLISHED",
        "text": "...",
        "created_timestamp": "..."
      }
    }

--- Endpoint 5: UI Guest Review Submission ---
POST /api/ui/reviews
  (Called by the mock website's "Submit Guest Review" modal.)
  Request Body:
    {
      "property_id": "800101",
      "reviewer_name": "Sneha Nair",
      "review_score": 9.5,
      "headline": "Superb stay!",
      "positive": "Spotless rooms and courteous staff.",
      "negative": "",
      "traveler_type": "Couple",
      "reservation_id": "RES-995102"  // optional; auto-generate if omitted
    }
  Response `201 Created`:
    { "review": { ...BookingReview } }
